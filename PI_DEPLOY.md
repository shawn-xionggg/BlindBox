# Pi deploy: the hat-camera punch detector (2026-11-22)

The same detector that worked live on the laptop (DEMO_SETTINGS.md), retrained on the keypoints the **Pi's pose model** produces, and exported to plain C.

## On the Pi (with qnx/vision_pi from main)

1. `git pull`, rebuild `qnx/vision_pi` (it compiles `qnx/model/early_model.c`, now the new detector).
2. Set the demo threshold, then start as usual:
   ```sh
   echo 0.828 > /data/home/qnxuser/blindbox_threshold
   sh qnx/pi_start.sh
   ```
   Too many false beeps: `echo 0.85 > ...`; too many misses: `echo 0.81 > ...`, then start again.
3. Old detector back: copy `models/archive/qnx_early_model_before_head.c/.h` over `qnx/model/early_model.c/.h` and rebuild (its old default was 0.923-0.949).

Caution: `vision.cpp` fixes its feature window at 12 frames (written for ~20 fps). The new detector was trained on ~30 fps hat sessions through `early_dataset.py`; if beeps look late or odd on the Pi, check that window against the Pi's real frame rate.

## What it is made of

| File | What it is |
|---|---|
| `yolo11n-pose.onnx` | pose model (the "YOLO" part): image -> 17 body keypoints |
| `qnx/pose/pose_decode.c/.h` | C decoder for the pose model's output (keypoints of the largest person) |
| `qnx/model/early_model.c/.h` | **the new detector** in C: `early_score(x)` -> probability that a fist just left guard |
| `models/archive/TESTED_pi_leaveguard_headonly_onnx.joblib` | the same detector in Python (scikit-learn), if Python runs on the Pi |

Threshold: use **`EARLY_THRESHOLD_DEMO`** from `early_model.h` (the Pi equivalent of the 0.82 that worked live on the laptop). Beep when `early_score(x) > EARLY_THRESHOLD_DEMO`. Raise it a little if there are too many false beeps, lower it if punches are missed (steps of about 0.01).

The feature order the C model expects is `EARLY_FEATURE_NAMES` in `early_model.h`; the features are computed exactly as in `early_live.py` (same code as training, see `test_early_live.py`).

## How it was made

1. `repose_onnx.py` re-ran the ONNX pose model on the 3 labeled hat-camera sessions (volunteers 3, 7, 8) -> `data_onnx/`.
2. Labels: start = the frame the fist **leaves guard** (`make_reactive_labels.py`), the same labels as the laptop model.
3. `early_detector.py --data data_onnx --test-mount head --train-mount head --budgets 2 4` (hat-camera sessions only, like the laptop winner).
4. `export_model_c.py` wrote `qnx/model/early_model.c/.h` and checked that C and Python give the same scores.

The previous Pi model is kept as `models/archive/qnx_early_model_before_head.c/.h`. The laptop models `models/early_detector*.joblib` are unchanged.

## Numbers (people it never trained on, hat camera, from the fist leaving guard)

| | caught <= 100 ms | <= 200 ms | <= 300 ms | false alarms/min |
|---|---|---|---|---|
| Pi model, strict threshold (0.929) | 25% | 40% | 49% | 4.1 |
| Pi model, looser threshold (0.916) | 36% | 53% | 61% | 9.0 |
| laptop model (tested live), strict / looser | 24% / 33% | 40% / 52% | 47% / 60% | 5.1 / 7.9 |

`EARLY_THRESHOLD_DEMO` = 0.828, lower again (more beeps, earlier), as on the laptop.

## Not verified

- **The C-vs-Python check didn't run** (no `gcc` on the laptop that exported it). The C was generated by the same exporter that was verified identical before. To check: `python export_model_c.py models/archive/TESTED_pi_leaveguard_headonly_onnx.joblib` on a machine with gcc (it rewrites the same files and compares), or compile `qnx/model/early_model.c` on the Pi.

- The full live loop on the Pi (camera -> ONNX pose -> features -> `early_score` -> buzzer): the repo's QNX side still runs a scripted vision stub (`qnx/vision_stub`).
- The threshold on the Pi: `EARLY_THRESHOLD_DEMO` is carried over from the laptop test, not tested on the Pi.
- Pi frame rate: the model was trained on ~30 fps footage. Much lower fps on the Pi will delay the beep.
